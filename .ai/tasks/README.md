# Individual Task Documents

このディレクトリには、機能追加やデータ構造の変更など、ひとまとまりの開発内容ごとの指示書を置く。

## 命名

ファイル名は `4桁の連番-開発内容.md` とし、開発内容には英小文字の kebab-case を使用する。

```text
0001-add-authentication.md
0002-add-user-pricing-table.md
0003-add-pricing-settings-ui.md
```

連番はタスクを一意に指定するための識別子である。実行順序を連番だけで判断せず、依存するタスクがある場合は本文の `Depends on` に明記する。

## 記載項目

```markdown
# <タスク名>

- Status: proposed | approved | in-progress | completed
- Depends on: none | <タスクID>

## 目的と要求

## 変更対象

## 対象外

## 守るべき仕様と制約

## 受け入れ条件

## 想定する検証
```

`Status` は次の意味で使用する。

- `proposed`: 内容の検討・レビュー段階。ユーザーが実装を明示的に承認するまで実装しない
- `approved`: 実装を開始できる
- `in-progress`: 実装または検証を継続する
- `completed`: 現在の実装を確認し、ユーザーが再開または追加変更を明示しない限り再実装しない

ユーザーから現在の依頼で明示された指示がある場合は、その指示を優先する。

AIへ作業を依頼するときは対象ファイルを明示する。指定されていないタスクは実装対象に含めない。

完了後も有効な仕様、設計、運用手順は `README.md` または `docs/` に反映する。タスク文書は実装時点の指示であり、現在有効な仕様の唯一の根拠として扱わない。

## 既存の記録

旧 `.ai/workflows/` から移した既存文書は、実装時の依頼を記録するため、元のファイル名と内容のまま保持する。新規タスク向けの命名・記載形式へ遡及的に書き換えず、現在の実装や仕様はコード、テスト、`README.md` から確認する。

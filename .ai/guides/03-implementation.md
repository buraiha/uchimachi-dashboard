# Implementation Guide

コード、設定、ドキュメントを変更する作業で使用する。

1. 作業ツリーと既存変更を確認する。
2. 対象箇所と関連テストを読み、変更境界を確定する。
3. 既存の設計、命名、エラー処理に合わせて小さく変更する。
4. 必要なテストやドキュメントを同じ変更範囲で更新する。文書は現在有効な本文へ統合する。
5. 関連チェックを行い、失敗の原因を切り分けて修正する。開発途中では採番しない。
6. 試験完了後、リリース前のコミットを行う際は、`.ai/common.md` の「バージョンと変更履歴」に従って採番・承認・更新を行う。バージョニング作業の完了はリリース完了後とする。

要求外のリファクタリング、依存更新、広範囲の整形を混ぜない。ユーザーの既存変更と未追跡ファイルを保護する。

未実装部分では、承認済みの要求に必要な初期構成・実装・検証手段を用意する。既存部分がある場合はその契約を守り、接続部分も検証する。必要十分な実装を、差分を小さくするためだけの場当たり的な追加で置き換えない。

設計書・要件正本と現行実装に不整合がある場合は、`.ai/common.md` の乖離レベル0〜3と停止・確認の規則に従う（パスはリポジトリルート基準）。文書か実装の一方へ推測で合わせない。

# うちまちダッシュボード 要件定義書

## 目的と利用者

Googleカレンダーの共有カレンダーで地域の予定を集約し、誰でも閲覧できる形で公開する。個人用カレンダーではなく、地域向けの公開サービスとする。

- 閲覧者：ログインなしで予定・地域告知を閲覧する。
- 管理者：掲載カレンダー、Google連携、地域告知、予定メモ・URLなどを管理する。
- 各団体の担当者：Google側で公開用カレンダーの予定を更新する。アプリの管理権限は持たない。

## 今回の対象と将来対応

今回の対象は閲覧と管理の分離、管理者認証の保護、チャート設定のブラウザ内保存、取得失敗時の公開向け案内とする。予定表示・表示件数・伝言の掲載期間・予定メモの既存仕様は合意した範囲で維持する。バックグラウンド取得とキャッシュ表示は将来対応とする。

## 合意済み要件と受け入れ条件

本書を現在有効な要件の正本とします。公開閲覧と管理の分離、およびチャート設定のブラウザ内保存は未実装です。現行機能・起動手順は[README](../README.md)を参照してください。要件の合意と実装済み・検証済みの状態は区別します。

| ID | 要件 | 受け入れ条件・想定する検証 |
| --- | --- | --- |
| REQ-001 | 共有カレンダーで地域の予定を集約・公開する。最初は1件でも運用でき、団体の参加に合わせて管理者が掲載対象を追加できる。各団体はGoogle側で自分たちの予定を更新する。 | 1件および複数件の掲載対象から予定を集約できることを確認する。 |
| REQ-002 | 閲覧者はログイン・アカウント登録なしで予定を見られる。閲覧の妨げとなる認証・同意等の手続きを設けない。 | 未ログインで公開画面を直接開いて予定を閲覧でき、管理者向けのGoogle認可を要求されないことを確認する。 |
| REQ-003 | 管理者専用ページを設け、掲載カレンダーの追加・変更・削除、Google連携、公開設定などの管理操作を管理者に限定する。 | 公開画面に管理用の操作を表示しない。未認証で管理画面や更新処理へ直接アクセスしても管理操作ができず、管理者だけが操作できることを確認する。 |
| REQ-004 | 複数カレンダーの集約、今日・明日・明後日以降の一覧、チャート表示は現行の仕組みを土台とする。 | 閲覧と管理を分離した後も、既存の予定表示が利用できることを確認する。 |
| REQ-005 | チャートは設定未保存の初回は非表示とし、閲覧者が必要に応じて表示に切り替えられる。表示日数の未保存時の初期値は3日分とする。表示・非表示と表示日数（2・3・7日）は閲覧者のブラウザのlocalStorageに保存・復元する。サーバーに閲覧者ごとの状態を持たず、閲覧操作で全体共通設定を書き換えない。 | 設定未保存時はチャートが非表示で、表示に切り替えると3日分が表示されることを確認する。再読み込み時に設定が復元され、別のブラウザへ影響しないことを確認する。設定保存のためのサーバー更新を行わず、保存できない環境でも閲覧・その場での表示切替を続けられることを確認する。 |
| REQ-006 | 管理者認証は既存のID・パスワード方式を基本とする。管理入口は公開画面に載せず、URLが知られる前提で認証により保護する。HTTPS、長く使い回さないパスワード、ログイン試行制限、Cookie保護、不正な更新要求への対策を点検・整備する。同じ管理者IDで15分間に5回ログインに失敗したら、そのIDでのログインを15分間停止する。停止中も公開閲覧には影響させない。管理者セッションはログインから24時間で失効し、再ログインを求める。利用中も有効期限を自動延長しない。 | 管理画面・更新処理の認証、15分間で5回失敗したIDの15分間のログイン停止と停止解除、停止中も公開閲覧できること、ログインから24時間経過後およびログアウト後のセッション拒否、有効期限が利用操作で延長されないこと、Cookie設定、不正な更新要求の拒否を検証する。本番HTTPSは実環境で別途確認し、未確認を区別する。 |
| REQ-007 | 掲載対象は公開用として運用する共有カレンダーとする。各団体が、説明文・関連URLを含め一般公開してよい情報だけを登録する。今回の範囲では、アプリに予定ごとの公開判定・掲載承認機能を設けない。 | 掲載条件を運用手順に明記し、Google側の限定共有がアプリ側の閲覧制限になるとの誤解を生まないことを確認する。 |
| REQ-008 | 伝言機能は、特に告知したい地域情報を期間限定で掲載する機能とする。掲載期間の指定・期限切れの扱いは現行仕様を維持する。登録・編集・削除は管理者に限定し、カレンダー担当者には操作権限を与えない。閲覧者はログインなしで読める。 | 未ログインで掲載中の告知を閲覧でき、掲載期間に関する現行動作を維持し、掲載期限後は表示されず、管理者以外は登録・編集・削除できないことを確認する。 |
| REQ-009 | Googleの説明欄からのメモ・URLの自動取り込みと、アプリ側での補足・上書き機能を残す。アプリ側の編集は管理者だけが行える。 | 自動取り込みと手入力優先・固定解除の現行動作を維持し、管理者以外からの編集を拒否することを確認する。 |
| REQ-010 | 当面の都度取得方式では、予定の取得失敗時に「予定を取得できません。時間をおいて再度お試しください」と公開画面に表示する。最後に取得できた予定を残して表示する対応は、将来のキャッシュ化と合わせて行い、最終取得成功日時と現在更新できていない旨を伝える。 | 当面は取得失敗時に案内が表示されることを確認する。将来のキャッシュ化時は、取得成功後に失敗する状況で直前の成功データとその取得日時が維持され、最新情報として誤表示されないことを確認する。 |
| REQ-011 | 将来はバックグラウンド処理でカレンダーを取得・キャッシュし、公開画面はキャッシュから表示する。 | 将来の実装時に、閲覧要求がGoogleへの都度取得に依存せず、取得失敗でも成功済みキャッシュが維持されることを確認する。 |
| REQ-012 | 当面は予定の表示件数を10・20・30・40件から選ぶ現行仕様を維持する。件数はカレンダーごとのAPI取得上限と、全カレンダー統合・時刻順整列後の最終表示上限の両方に適用する。 | 各選択値で既存の取得・統合・表示上限が維持されることを確認する。 |
| REQ-013 | スマホ・PCの両方で予定・地域告知を閲覧できる。主な確認対象はSafari・Chrome・Edgeの最新版とする。 | 実装検証時点の対象ブラウザ・OS・端末または検証環境を記録し、スマホ幅・PC幅で予定と地域告知の閲覧、チャートの切替・設定復元を確認する。未実施の環境は検証済みとしない。 |

現行実装はダッシュボード表示・更新の要求ごとにGoogleから予定を取得し、取得済み予定を保持するキャッシュはありません。当面は都度取得を維持して失敗時の案内を整備する方針です。バックグラウンド取得・キャッシュ表示と、失敗時の成功データ表示は将来対応とし、今回の要件合意でキャッシュを実装するものではありません。

localStorageの設定は端末・ブラウザ間で同期しません。将来のキャッシュ方式で取得成功データがない場合の公開表示、キャッシュの取得間隔・保存先・古い情報の扱い、管理者認証の保護に関する具体値・実現方法は今後整理します。対象OS・端末の具体的な検証環境と実機検証の結果は、実装時に記録します。

現在は要件整理の段階です。要件合意だけでは実装や公開設定の変更を行いません。
